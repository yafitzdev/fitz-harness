01 · What it is

One sentence each for the three things this project actually is.

apps/desktop
🖥️ A Codex-style agent desktop app

Electron shell with a sandboxed renderer: three-pane layout, floating composer, project sidebar, activity timeline with tool disclosures, and a right-hand Inspector. Vanilla TypeScript DOM — no React.

apps/host
⚙️ An inference control plane

Long-running local service (127.0.0.1:8787) that owns model lifecycle, routing, queueing, security, quotas, and telemetry. The desktop window is just a client — closing it doesn't stop the host.

packages/*
📦 A framework of packages

Fourteen TypeScript packages separated by responsibility: protocol, inference-core, engine adapters, agent-core, context, storage, security, connectivity, media, and observability.

Design principles

  • Local-first — everything runs on your machine; models live under C:\Users\yanfi\.llm, engines under .llm/engines.
  • Process separation — host, desktop renderer, engine processes, and WSL inference are independent, individually restartable processes.
  • Secret-safe by default — HMAC bearer tokens, redaction of secrets in every log/event path, safeStorage for device credentials.
  • Resumable everything — SSE with Last-Event-ID, durable transcripts, crash recovery, deterministic compaction.
  • No shell-concatenated launch commands — engines are always spawned as executable + argv arrays.

02 · Architecture

Three tiers, cleanly separated: a control-plane host, an Electron desktop shell, and 14 framework packages.

Key properties

  • The host is the owner. Engine lifecycle, queues, and security live in the service, not the window. Any number of UI clients can attach.
  • The renderer is a client. It talks to the host over a typed, versioned protocol (@fitzcodex/protocol) — requests, events, and SSE streams.
  • Adapters are the boundary. inference-core defines the adapter contract; each engine (ninfer, llama.cpp, openai-compatible, fake) implements it behind the same state machine.
  • Pi is behind a Fitz-owned boundary. agent-pi wraps the Pi SDK (0.83.0) so upgrades don't leak into the rest of the codebase.

Lifecycle & operations

  • On-demand loading — models are loaded only when first requested, then served from memory.
  • Idle eviction — a 600s idle TTL unloads models that aren't being used.
  • VRAM governance — a 2 GiB reserve policy prevents overcommitting GPU memory.
  • Single-generation queue — one generation at a time, FIFO, with route-based budgets.
  • State machine — UNLOADED → PREPARING → LOADING → READY → BUSY → …, with explicit failure and eviction states, surfaced as typed events to clients.
// Lifecycle states exposed over the protocol
type ModelState =
  "unloaded" | "preparing" | "loading" |
  "ready"    | "busy"     | "evicting" |
  "failed"   | "terminated";

05 · Agent runtime & sessions

Pi SDK sessions behind a Fitz-owned boundary, with durable approvals and crash recovery.

Capabilities

  • Allowlisted coding tools — only the sanctioned toolset is exposed to the agent.
  • Access modes — full, ask, and read-only constrain what the agent may do per session.
  • Durable pre-execution approvals — tool executions are gated until approved; decisions persist across restarts.
  • Event translation — Pi's internal events are translated into sequenced Fitz events for the UI and consumers.
  • Resumable SSE — clients reconnect with Last-Event-ID and never lose progress.
  • Crash recovery — interrupted runs are detected and resumed from durable state.

Context & compaction (context package)

Token budgets are enforced at an 80% threshold. The canonical transcript is always preserved while a deterministic summarizer compacts the working context; both automatic and manual compaction are supported. Because compaction is deterministic, the same input always yields the same summary — runs stay reproducible.

07 · Desktop experience

Codex-styled UI, built from extracted vanilla-TypeScript controllers.

  • Three-pane layout — sidebar (projects/sessions) · conversation · right Inspector.
  • Floating composer — model, effort, and temperature controls inline with the input.
  • Activity timeline — every tool execution is disclosed in sequence with its result.
  • Inspector — file diffs, rendered markdown, sandboxed HTML previews, and media artifacts.
  • Connection workspace — Tailscale pairing and remote-device management.
  • Message actions — copy, retry, and per-turn controls on messages.

UI is composed from extracted controllers (AgentRunController, ActivityTimeline, ProjectSidebarController, ComposerControls, ConnectionWorkspaceController, PluginCatalogController, ResourceInspector) plus layout and popover primitives — all plain DOM, no framework.

09 · Quickstart

Getting from a fresh clone to a running system.

# 1 · install workspace dependencies
pnpm install

# 2 · typecheck + run the full test suite
pnpm check

# 3 · start the local control plane (host)
pnpm --filter @fitzcodex/host start

# 4 · launch the desktop shell in another terminal
pnpm --filter @fitzcodex/desktop start

The host binds 127.0.0.1:8787; the desktop attaches as a client over the typed protocol. Models are loaded on demand from C:\Users\yanfi\.llm.
