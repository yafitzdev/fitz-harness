# 三插件机制分析

调研日期：2026-08-16
来源：三个上游仓库已克隆到 `_upstream/`，并对照本机 DSH 已装配插件与 `agent-presets` 源码确认。

## 1. J-Space Cognition Suite V3.6

仓库：https://github.com/Tiger3807861189/J-Space-Cognition-Suite-V3.6
源码：`_upstream/J-Space-Cognition-Suite/`

### 形态

它不是 DSH bundle 插件，而是标准 Skill 包。入口是 `j-space/SKILL.md`，通过 `fast / full / loop` 门控按需加载 `modules/` 中的 9 个协议模块；`scripts/jspace.py` 是可选的 Python 账本控制器。

### 核心机制

- **J-space premise**：用“可报告、可主动保持、可广播”的推理时工作空间建立控制框架。
- **选择性工作空间**：只让 1-2 个连贯项目进入活动区，其他状态外化到账本。
- **三寄存器**：内部 `inner` 稠密轨、外部 `ledger` 持久状态、面向用户/工具的 `outer` 清洁输出。
- **Dense Track**：`✓ / ? / ✗` 标记验证、待验证、证伪；每行必须可无损展开。
- **Bridge-before-conclusion**：强制中间概念先于消费它的结论出现，防止结论先行的合理化。
- **Metacognitive control**：置信度必须选择动作，不能只当注释。
- **Empirical escape**：推导停滞时转为有限候选集、独立参照和差分测试。
- **Verification/recovery**：checkpoint 必须带 verifier 与 coverage；meltdown 有固定恢复序列。

### 与 DSH 的结合点

- 它提供的是“怎么思考、怎么保持状态、怎么验证”的协议层。
- 它不选择模型行为带，不按任务类型切换 persona，也不做 system-prompt/assemble 注入。
- Python 控制器可被 DSH 插件用 Node 账本工具替代，更适合宿主内生命周期。

## 2. oh-we-need

仓库：https://github.com/scp3500/oh-we-need
源码：`_upstream/oh-we-need/`

### 形态

纯提示词，`prompt.md` 全文只有 11 行，零依赖。目标是 DeepSeek V4 系列，不声明兼容其他厂商模型。

### 核心机制

- 以 `we need to ...` / `we need ...` 作为 CoT 核心句式。
- 交错使用 `I'll / I can / I need / I should / I will / I'm` 表达下一动作、可行项、必须项、承诺与正在进行项。
- 避免 `let me ...`。
- 每条推理一个具体动作，短句、决策级摘要。
- 任务先分类：`build / fix / weak`。
- 思考放在 thinking tag 内，最终回复不泄露 reasoning。
- 原理是上下文条件化：DeepSeek V4 每轮 CoT 由当前上下文重新生成，提示词稳定注入后每轮都生效。

### 与 DSH 的结合点

- 它强化 V4 推理的“第一人称能动性 + 每步一个动作”，正好补上 J-Space 的 First-person agency。
- 它没有路由能力，也不管理状态。
- 最优注入位置是系统 persona 或 near-field 用户消息后引导，不能放进会变化的动态 system 前缀。

## 3. dsh-routing-suite

仓库：https://github.com/yjh051108/dsh-routing-suite
源码：`_upstream/dsh-routing-suite/`
子模块：
- `injector`：dsh-super-injector
- `preset`：dsh-router-standard
- `mode-boost`：dsh-mode-boost

### 形态

一个聚合仓库：注入器负责运行时插件管理，preset 负责 agent 平面路由，mode-boost 是宿主平面增强插件。

### 注入器机制

源码：`injector/src/index.ts`

- 通过 `ctx.loader.create({ name, config })` 运行时装配标准插件包。
- 用 junction 链接到 profile `node_modules`，不碰 patch/package.json。
- 持久化清单到 `$DSH_HOME/super-injector/registry.json`，重启恢复。
- 提供热重载、staging、卸载、路由自愈和 client UI。
- 本机已装配 `dsh-super-injector`，当前 GUI 的 `dev_*` 工具即来自它。

### router-standard / router-spec 预设机制

源码：`preset/preset/router-standard/router-bootstrap.mjs` 与 `router-core.mjs`

- 监听 `system-prompt/assemble`，在首个模型请求前读取真实用户消息。
- 用外部分类器选择稳定行为带：
  - `spec`：计划优先，`read/edit/glob/grep`
  - `react`：执行者，`read/write/edit`
  - `weak`：弱 persona 内路由，RL 形工具面 `shell + str_replace_editor`
  - `mixed`：过渡带，实测不稳定，只有显式选择才会进入
- 首个持久 `tool/call` 后恢复完整 Standard 工具目录，避免中途改 schema 破坏缓存。
- 监听 `session/event`，weak 会话在每条真实用户消息后追加一条固定/半固定 near-field 引导。
- 提供 `dev_router_status / dev_router_mode / dev_mode_subagent` 让模型自优化。
- 保留 plan-mode section，只替换 persona section。
- 实测依据是 P1-P23 探针：模式选择必须来自外部，模型自身不能稳定自路由。

### mode-boost 机制

源码：`mode-boost/lib/index.js` 与 `lib/core.js`

- 宿主平面 bundle 插件，装配在官方 preset 之上，无需 fork preset。
- 与 router-standard 的共存守卫：检测 `router-persona` section 或 `dev_router_status` 工具名，存在则整体 no-op。
- 对寒暄会话整体让位，避免深度 persona 套在聊天上导致长链。
- 第 3 轮起使用“新任务，重新分类”的 boost 引导，避免上一任务风格稀释。
- 简单任务快速收敛，复杂任务有向深度，Pro 模型追加决策闭环后缀。
- 本机已装配 `dsh-mode-boost`；当前会话使用 router-standard preset，因此 mode-boost 按守卫让位。

## 三者的关系

| 层 | J-Space | oh-we-need | dsh-routing-suite |
|---|---|---|---|
| 外部任务路由 | 无 | 只做 build/fix 分类 | 有 |
| 行为带选择 | 无 | 无 | spec/react/weak |
| 推理协议 | fast/full/loop | we need 句式 | 深度/收敛引导 |
| 持久状态 | 有 Python ledger | 无 | 无 |
| 验证与恢复 | 有 | 无 | 无 |
| DSH 集成 | Skill | prompt | preset + bundle plugin |

结论：routing-suite 负责“选模式、选工具面、近场引导”；J-Space 负责“选协议强度、保持状态、验证”；oh-we-need 负责把 V4 的推理文本改造成“每步一个动作的第一人称工程思维”。三者没有实质重叠，可以合并成一个 DSH agent preset。
